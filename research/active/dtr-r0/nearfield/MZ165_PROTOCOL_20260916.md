# MZ165: pretrained visual context for direct corridor decisions

EXPLORE, consumed original TRAIN192, 2026-09-16.

Question: do frozen pretrained spatial features improve direct obstacle decisions
over an identically shaped frozen random encoder? MZ161's small random local CNN
underfit FIT; MZ140-142 used pretrained visual features for metric-depth fusion,
and MZ164's metric output confused foreground and background. Here the output is
direct corridor risk, without constructing or calibrating a depth map. This is
not the first pretrained backbone in this project or a new foundation model.

## Frozen contrast

Use official DINOv2 ViT-S/14 without registers, final normalized patch features.
The two encoders have the same architecture: official pretrained weights versus
random initialization at seed165016. Both stay frozen/eval; source revision,
weights and state hashes bind in the download/adapter receipt and execution
freeze before real extraction. No UniDepth or depth-finetuned weights are used.

Full native RGB360x640 is bilinearly resized to518x924 and ImageNet-normalized.
Each encoder returns384x37x66 embeddings. A shared trainable1x1 projection maps
384 to24 channels, bilinearly enlarges to360x640 and adds to the MZ161 native
22-plane stem before SiLU. Its original24-channel local residual blocks and
independent132 raw ToF/Radar token branch remain. Both arms receive native RGB
detail, all public slots, camera/body rays and packet validity. No IDs, family,
source truth or evaluator data are predictor inputs. Coarse embeddings and
upsampling do not establish fine localization or translation equivariance.

Both new decoders start identically at seed165016 and use the same20 epoch
orders, batch4,720 AdamW updates, lr0.001, weight_decay0.0001. Both minimize
frame BCE plus balanced known-pixel BCE, using the original MZ161 losses and
labels. No augmentation, scheduler, checkpoint selection or early tuning.
The frame decision is the unchanged maximum of query-eligible pixel and
independent return logits, cutoff0. Dense loss supplies direct local gradients;
the frame maximum can still starve the losing return branch, which must be
reported rather than assumed cured. Raw input retention is not alert retention.

Report FIT and HELD whole-frame precision/recall, TP/FP/FN, UNKNOWN, ordinary
versus boundary-pressure, every family, matched pairs, true-frame retention,
events/onset, false segments and native contributor retention. Also report
known-pixel precision/recall, risk half-column coverage, off-corridor target
activation, unknown-positive pixels and pixel/return winners. Per-return Radar
lineage remains NOT_EVALUABLE. Neither input availability nor a global score
substitutes for measured native retention.

FIT nonalert containing a returned native corridor contributor, and HELD:
all MZ129 true frames/events/timing retained, FP<=floor(0.75*baselineFP), no
