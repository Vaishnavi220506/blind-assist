## Interpretation and preserved limits

Matched-control attribution condition: False. This condition
requires fewer FP than the control on at least one panel and no lower total TP
on any panel; it does not replace exact true-frame, event, family and native
retention. Binary pair counts include ties; sampled-bin time uses synthetic
4 Hz cadence. UNKNOWN means nonalert, not clear space. Native counts describe
returned samples, not complete surfaces; Radar per-return lineage is NOT_EVALUABLE.

The original fitted model is sensitive to horizontal reflection on TRAIN192:
mean absolute score difference 0.148918, maximum 0.939466.
This is a fitted-model diagnostic, not proof that symmetry causes all nuisance.
The two-view mean is invariant to swapping its inputs by construction; this
algebraic property alone does not prove better alerts or realistic acquisition.

The separate posthoc MZ158 HEAD diagnosis finds 16 shared learned false alarms.
All have target geometric hits, 15 have valid target ToF returns, and none has
a returned native corridor contributor. Target lateral clearance is about
18.09-21.19 cm. All 16 are left-side, but 30 of 36 negative frames are left-side
and scene geometry/texture differ. This supports a shared off-corridor learned
nuisance problem, without isolating symmetry as its cause. No diagnosis-derived
family selector or threshold enters the candidate.

## Implementation, checks and execution

Reflect RGB pixel centers, camera lateral offset, yaw, ToF columns/theta bounds
and observed Radar angles, then re-sort Radar tuples and re-extract features.
Both views preserve the original public slots, masks and uncertainty. Discarded
Radar returns cannot be regenerated. Each view has weight0.5 and stays in the
original scene fold. Minimum leaf rows16 match the doubled-view control, but
reflected rows may partition differently; identical regularization is not assumed.

Three focused tests pass: transformation involution/nonmutation, geometric rays
and support under nonzero extrinsics, and symmetric scores/causal flags. Original
features are checked bitwise against authenticated caches on every scored frame.
Four grouped OOF fits plus one final fit run once per arm. Models, cutoffs and
dev predictions remain unchanged across mechanical recovery.

Execution uses OpenCV4.10/sklearn1.9 on CPU, GPU_BACKEND_UNAVAILABLE. A backend
probe measures the actual implementation; no CUDA or device-latency claim.

## Mechanical recovery and access-scope exception

The initial process finishes fitting, dev predictions and scoring, then exits
on a post-score SHA helper receiving a string instead of Path. The first resume
finds MZ146 historical incumbent predictions wrapped in a dictionary, before
later inference. Repairs normalize Path and unwrap that existing dictionary.
Saved dev outputs and models are authenticated and reused; no refit, dev rerun,
source selection or algorithm/threshold change occurs. Frozen original code,
exact repair diff, original and resumed identities remain in the artifact tree.

**Access clarification:** the inherited incumbent cache contains mixed splits.
The initial loader decodes cached original-test prediction values into a lookup
alongside TRAIN/dev values; those test entries never reach selected feature, fit,
calibration or evaluation paths. Original test raw/evaluator records and RGB
are not decoded and no new test model scoring occurs. The initial broad
`original_test_access=False` fields and protocol wording are therefore overbroad;
they do not establish complete test-cache isolation. This exception is preserved
rather than rewriting the initial frozen run or claiming untouched test metadata.
After the run, tracked metadata keys are narrowed to explicitly state no test
raw/evaluator access and acknowledge decoded-but-unused cached test predictions.
`postrun-scope-clarification.json` records this metadata-only change; frozen
original code and output fields remain intact.
