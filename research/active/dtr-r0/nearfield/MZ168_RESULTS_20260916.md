# MZ168: visual yaw improves some angles, with no corridor-decision gain

EXPLORE consumed FIT144, 2026-09-16.
[Protocol](MZ168_PROTOCOL_20260916.md).

Decision: **MZ168_FIXED_VISUAL_YAW_NOT_ADMITTED**. Visual homography rotation is
accepted in 26 of 120 noninitial frames. All-frame yaw MAE falls from 0.15004
to 0.14070 degrees, but the fixed exact-range oracle remains **69 TP / 1 FP /
3 FN**, with the same 0.50 s delayed event and 35 native corridor contributor

range, full-system alert replacement or fresh confirmation was run.

## What changed

The component uses only causal RGB, calibration, public pitch and IMU. It fits
reference-to-current homography from bidirectionally checked LK tracks, then
decomposes calibrated H into rotation/translation/plane-normal hypotheses.
It explicitly checks rotation validity, positive-depth compatibility and yaw
agreement across branches. Accepted rotation supplies yaw; rejected proposals
use the unchanged public IMU integral. Visual yaw is never fed back into that
integral. Public pitch, camera offset and all ToF/Radar returns are unchanged.

The same public initial-forward convention supplies each time0 anchor. Camera
translation and moving foregrounds remain in these scenes; a dominant static
plane is an assumption, not established by inlier count. This differs from
MZ148's image residual features and MZ119/MZ160's ToF-scaled parallax. It does
not estimate an absolute body heading or metric translation.

All 144 observable poses seal before saved MZ167 slant, known masks, native
masks, cases and reference yaw are decoded. Parent IDs/family/group metadata
are read earlier for bookkeeping but never passed to the estimator. The original
IMU projection reproduces all 144 saved masks exactly. Only yaw changes in the
new projection; reference range and known-pixel availability remain evaluator-
only, so a successful pose component would still not be a deployable detector.

## Execution, repair and validation

Seven synthetic tests pass, covering calibrated rotation plus translation,
OpenCV/project axes, pure rotation, ambiguous branches, tracking, invalid-IMU/
gap/reset behavior, immutable metadata and prefix causality. A reproduced
OpenCV 4.10 near-pure shortcut can return a slightly nonorthogonal matrix for
tiny translation; this is rejected without polar-projecting it into a rotation.
Nonpure positive-depth-filter failure also falls back explicitly.

All 144 poses are saved by 5.59 s including setup/hash time. Pose and mask
generation execute once. Aggregation then encounters a KeyError because 11
original empty native Counters serialize without zero-valued count keys.
The producer source confirms zero-count semantics. Five reducer accesses are
changed to `get(key, 0)`; the original runner is preserved with its frozen hash.

A saved-output-only recovery initially selects the wrong AST block and fails
before the loop or output writes. Its failure log is retained; the corrected
selection runs only aggregation. Every sealed pose, mask, case, freeze and seal
hash stays identical. Completion includes the mechanical repair receipt and
original/repaired source hashes. Total wall time including repair is 227.09 s,
within the original 600 s allocation. No image tracking, mask calculation,
training or capture is repeated; no scientific parameter changes.

Independent saved-output audit passes 253 hash comparisons across 235 unique
paths, all 288 independently reconstructed IMU/visual masks, and 432 pixel/
column reductions. It authenticates the frozen original runner and exact five
Counter replacements, unchanged six scientific products and all 11 omitted-
count cases. Metrics, paired flags, native counts, events and gates reproduce.

The audit checks SO(3), yaw extraction and ranking for 176 saved solutions in
44 decompositions, plus 4,148 sampled tracks and 3,769 sampled survivor-visibility
checks. It does not rerun tracking or homography estimation. Only up to 64 point

Original runner, recovery and audit processes have exited; no task runtime remains.

## Disposition

Visual acceptance and lower overall/boundary yaw MAE pass. Native true-frame
retention, zero false frames, original onset timing, every-family spatial
accuracy and native-supported-nonalert conditions fail. Retain only the scoped
observable yaw effect and measured coverage failure; close this fixed complete
recipe as an intended NEGATIVE_CONTROL. No tracking/RANSAC/branch-tolerance
tuning or learned-range follow-up is justified by this result. Keep MZ129 and
MZ158's separate measured partial gain. The broad research goal remains active.

Durable poses, masks, logs, repair evidence and source receipts stay under
`artifacts.local/work/mz168-visual-yaw-20260916/`. No paid allocation or worker
is used. This is controlled simulation evidence, not hardware, natural-scene,
default-App or safety validation. Supported registration and inheritance both
exit2: pre-existing ledger303 input-fingerprint mismatch, then unknown terminal.
Both ledger files remain hash-identical; structured metadata is pending and no
manual append or bypass occurs.
