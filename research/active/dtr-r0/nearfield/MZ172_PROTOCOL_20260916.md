## Question and changed representation

Can registered visual context distinguish supported inside/outside returns and
improve final warnings? Add a contextual ToF head to the unchanged pixel path
and independent raw 132-return MLP. Each ToF slot queries 64 fixed cell-center
samples across its full public angular zone: native 22-channel detail, projected
24-channel frozen-DINO context, and within-zone position. Relative ray/corridor
information already exists in the public detail channels.

The registered arm uses learned query/key attention. The pooled arm uses a
uniform average of the same visible samples. Both allocate the same modules
and initialize identically; pooled query/key parameters are inactive by design.
This is an association-mechanism ablation, not equal effective model capacity.
The trainable DINO projection is shared with pixels, so context supervision can
also change pixel training; this is a complete representation intervention.
Values pass to the same contextual-return head. Each ToF output is the maximum
of its raw and contextual logits; Radar remains raw-only. Final frame output
remains the maximum over independent return and eligible pixel logits, cutoff0.
No previously failed predictor is added by a posthoc OR.

Samples are unshrunk full-zone cell centers, not selected private hit locations.
Outside-image samples supply no context, and all-invisible zones fall back to
raw returns. Partial RGB visibility never changes ToF/Radar validity. Attention
weights are learned associations, not certified ownership or physical support
deletion. The unanchored image path remains available for absent ToF returns.

Both arms use frame BCE + balanced known-pixel BCE + one balanced known-ToF-slot
BCE on the combined return logits, identical to MZ171 witness supervision.
Use seed172016,20 identical epoch orders,720 AdamW updates,batch4,lr.001,
weight_decay.0001. No loss weighting, epoch, threshold or checkpoint selection.
All raw/contextual/combined slot logits, attention weights, maps and flags are
saved. Float32 compute/output, TF32 disabled; existing feature caches float16.
cuDNN uses deterministic settings; CUDA grid-sampling backward is not asserted
bitwise repeatable. Model/output sealing, rather than replay equality, preserves
the executed result. The same orders and initialization remain required.
