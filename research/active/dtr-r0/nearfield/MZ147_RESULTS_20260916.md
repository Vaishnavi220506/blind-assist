## What the separate MZ146 diagnostic establishes

Read-only reconstruction of72 consumed rod frames exactly matches every frozen
MZ143 feature vector. Actual paired features are never identical;33/36 pairs
have correctly ordered scores. Elementwise pooling discards joint assignments,
but that fact does not establish it as the sole cause of false alerts.

Twenty-four of29 false rod alarms have no proposal/range tuple intersecting
all three query dimensions;25/36 true alarms also have no such tuple. A hard
geometry veto would therefore remove true support. In one observed false
tuple, a1.94m return is paired with a wider horizontal image edge, creating
an apparent corridor overlap. Native evaluator explanation places that return
on a3.47cm-wide rod outside the corridor. This is a correspondence error before
pooling, and evaluator ownership never becomes a predictor feature.

The rod is absent from returned native ToF lineage in16/36 true and16/36 false
frames. Absence includes missing packets and private-ray sampling gaps; it is
not observed free space. This supports testing evidence that can survive
intermittent near returns. It does not justify changing the completed MZ146
confirmation, declaring a new method successful, or suppressing independent
ToF/Radar observations. Full diagnostic examples and fixed first-frame images
are in `diagnostic/` under this experiment's artifacts.
