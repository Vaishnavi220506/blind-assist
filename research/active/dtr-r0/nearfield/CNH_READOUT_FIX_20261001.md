# 读出修复试点：分辨率和数据配比都没有集成层面的收益（快车道，2026-10-01）

**结论：按预设判读，RES（横向分辨率）为 UNCERTAIN，REBAL（角落数据配比）为 NO_EFFECT。** 两者在角落主区域都没有带来可用的收益，护栏区域也没有明显代价。

更关键的是：在这批新单位上，5 种子集成的基线在角落 B4 的 AUC 已经达到 0.939，与其他格子（0.93–0.95）相当。这次准备修复的"全覆盖角落差距"，在集成之后本来就很小。之前的 0.907 来自覆盖扫描中的 3 种子集成，评估单位也不同。

区间为分层 bootstrap（同时重抽评估单位和训练种子），共 2000 次。每格每组 P=144、N=432，来自 144 个新评估单位；AUC 取 HEAD/BODY 的平均。

|比较（相对 BASE）|主区域（角落 B3+B4）ΔAUC|护栏（其余 8 格）ΔAUC|判读|
|---|---|---|---|
|RES：第一层横向不降采样|−0.009 [−0.023, +0.006]|−0.002 [−0.007, +0.004]|UNCERTAIN|
|REBAL：一半面板换成角落大面板|+0.003 [−0.006, +0.019]|−0.004 [−0.009, +0.002]|NO_EFFECT|

**单模型与集成（事后描述，不进入判读）。**

|区域|BASE 单模型均值 → 5 种子集成|RES|REBAL|
|---|---|---|---|
|角落 B3|0.904 → 0.920|0.901 → 0.916|0.916 → 0.931|
|角落 B4|0.910 → 0.939|0.903 → 0.926|0.924 → 0.935|
|角落 B0|0.935 → 0.945|0.934 → 0.942|0.930 → 0.939|
|随机 B4|0.911 → 0.928|0.911 → 0.925|0.908 → 0.920|

- **集成本身的效果最大。** 5 种子集成比单模型均值高 0.01–0.03，在角落 B4 最明显（+0.029）。这说明角落里单个模型的弱点有很大一部分是训练方差，集成就能消掉。
- **REBAL 改善了单个模型在角落的表现**（B3 +0.012，B4 +0.014），但集成后只剩 B3 +0.011、B4 −0.004；同时在角落 B0 和随机 B4 略有下降。它的作用和集成大体重叠。
- **RES 训练损失更高**（末轮 0.20–0.25，BASE 约 0.15–0.18），各区域也略差。同样的参数量下，横向感受野相当于变小了，这可能是原因，但没有单独验证。

**对研究问题的含义。**

- 全覆盖时，角落中剩余的读出不敏感在很大程度上属于单模型方差，5 种子集成就能基本消除。更高的横向分辨率和更多角落数据都没有在集成之后再带来收益。
- 所以研究内容二的主要杠杆仍然是结构覆盖。覆盖内的角落问题，工程上用集成处理就够了，不必作为方法创新点。
- 之前表示可分性检查中 0.68 的 d′ 比值，用的是 3 种子集成、单帧输出。它可能部分反映了单模型方差，这一点没有在集成、平滑后的输出上重测。

**范围与限制。**

- 两个修复各只试了一种设置：一种步长、一种配比比例。
- 主区域是人为加密的子空间。
- BASE 的种子 0–2 是试点冻结模型，种子 3–4 为新训，两者训练代码的读取方式不同，但数据、顺序和配方相同（见偏差说明）。
- 结论只适用于当前生成器。新单位 87000–87143、88000–88047 用过一次后即为已消费 Development。

**执行与偏差**（详见 `DEVIATIONS.md`，都没有改动科学内容）：

- 评估集首次渲染因启动时写同一个临时文件而失败，重启后正常。
- 应用户要求提速：评估集改为 6 个进程分片渲染；体素化改为"单位文件能完整读出才处理"；训练数据一次性载入显存，每步对同样的 256 行做一次前向，等价于原先 4×64 的梯度累积。
- 第一次提速训练因显存不足失败（渲染进程占用显存），改为等渲染完成后再训练。
- 用时：评估集渲染约 25 分钟；训练中 BASE、REBAL 每轮 6–12 秒，RES 每轮 10–23 秒（期间与体素化争用 GPU）。
