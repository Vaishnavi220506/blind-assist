## Fixed observable component

Keep one RGB, 8x8 dual-return ToF, Radar and IMU. This component reads native RGB,
intrinsics, public pitch, time/episode boundaries and public IMU yaw increments.
It does not use regional ToF as point depth, metric translation, source camera,
scene family/identity, native object geometry or the simulator's known IMU bias.
All sensor returns and original alert branches remain unchanged.

Use each episode's time0 image as a causal reference, with the same initial
forward alignment assumed by the existing IMU integral. Reference age must be
<=1.5s and each consecutive interval must be0.25s within1e-6s. A missing start,
gap or invalid IMU invalidates the visual anchor until the next episode; the
original valid-increment IMU integral remains the fallback. No future frame or
retrospective smoothing is used. RGB does not recover absolute body heading.

At native resolution, goodFeaturesToTrack uses max1200, quality.01, spacing6,
block7. Pyramidal LK uses window21, maxLevel3, criteria30/.01; retain in-bounds
bidirectional tracks with return error<=.5px. RANSAC homography maps reference
to current, threshold1px, max2000iterations, confidence.995, RNG168016. Require
>=40 retained tracks and inliers, inlier fraction>=.6, and inlier bounding-box
spans>=.4 of image width and height. These are fixed engineering checks.

Decompose H with the public calibration into rotations, translation/plane-normal
hypotheses, and apply positive-depth filtering to normalized matched rays.
Nonpure decomposition with unavailable/failed depth filtering must fall back.
Require numerical SO(3) validity: Frobenius norm of R-transpose R minus identity
and absolute determinant error must each be<=1e-6. Do not silently orthogonalize
a near-pure OpenCV shortcut that mixes small translation into its returned R.
Collapse duplicate rotations within1e-6 degrees. Compute each surviving yaw
using the reference camera-to-body basis and R transpose, with correct OpenCV
right/down/forward versus project forward/right/up axes. All surviving distinct
rotations must agree in circular yaw within.10degrees; otherwise fall back.
Among agreeing branches, choose the rotation nearest the public IMU relative
rotation in SO(3), requiring distance<=1degree. Save every branch, distance,
best/second margin, yaw spread, matching statistics and fallback reason.
These tolerances are not calibrated uncertainty. Pitch/offset stay public.

The source has camera translation and moving foregrounds; a dominant static
plane is an unverified estimator assumption. Many inliers or a well-fitting H
do not independently establish camera motion. Homography rotation ambiguities
must be reported. The [OpenCV homography tutorial](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)
documents calibrated decomposition and its multiple solutions; the task-specific
checks and acceptance criteria here are our own, not a reproduced result.
