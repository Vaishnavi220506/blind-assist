# MZ120: single-frame learned spatial ownership, same-input Development pilot

The new user-provided direction supersedes the previous MZ119 optimization stop
for this bounded first round. Preserve MZ116 unchanged. No CNH, parallax, plane
solver, learned history, extra sensor, or final OR enters the new predictor.

Question: can RGB local features and actual multi-return ToF/Radar/IMU inputs
reduce false alerts without sacrificing critical current-body occupancy?
Hypothesis: explicit spatial supervision can replace erroneous hand allocation.

Start with MZ115 and MZ117 consumed captures; split complete episodes within each
source/family, deterministically assigning the last sorted episode in groups of
at least two to development, except MZ117 clear_ghost uses the first episode so
development includes a persistent ghost as well as an empty reference. This
coverage correction is fixed before training. The remaining episodes train. Do not split adjacent
frames across sets. MZ119 is a separate consumed transfer diagnostic, never fresh
confirmation; its templates are related to the other panels. Existing outcomes
are known. If the development pilot fails, stop this recipe and do not collect
fresh data, add a suppressor, or automatically launch CNH. If it passes, the
user's new-scene check remains necessary before a positive conclusion.

Runtime sees RGB pixels, calibrated intrinsics/extrinsics, two separate ToF
target slots with distance/sigma/signal/status/packet validity, four Radar slots
with available range/angle/Doppler/validity, and IMU orientation. Deterministic
causal IMU integration is reused; no previous image/range/alert becomes input.
No invented Radar quality. Native object bounds and body origins supply labels
only in the training/evaluator layer. No private histograms or hit lineage.

Occupancy labels are AABB intersections for 45 cells: height .4–1.5,1.5–2.05,
2.05–2.7m; lateral -1.5–-.3,-.3–.3,.3–1.5m; forward .2–1.4,1.4–2.6,
2.6–3.2,3.2–3.6,3.6–4.2m. These are volume occupancy, not surface depth.
Alert is the maximum probability over central lateral cells below2.05m and
within3.6m. Other outputs remain spatial diagnostics. Below threshold means
NO_ALERT_UNKNOWN, never certified CLEAR. Report HEAD and true near-rod cells
separately so a different alarm cannot conceal wrong localization. Rod metrics
join evaluator-only source actor roles to native bounds, including weak and
occluded rods inside mixed-family episodes; roles never enter runtime tensors.

One fixed small CNN with full640×360 pixels and a stride2 high-resolution branch;
7×7 projected cell samples; angularly local attention over uncollapsed ToF
target slots; separate Radar set attention. Train from scratch with seed120013,
AdamW lr.001, weight decay.0001, batch8,800steps; class-weighted spatial BCE only.
No checkpoint or architecture sweep; use the final model. Training-only global
brightness/contrast variation. Runtime budget:20minutes for training; abort
without interpreting a partial model if exceeded. GPU backend and real times
must be recorded. Source/model/split/prediction hashes and checkpoint retained.

Choose one threshold on development: minimize FP subject to frame recall within
2 percentage points of MZ116 and no newly missed complete event; ties prefer
greater threshold. If no threshold qualifies, report that and use the maximum
recall point diagnostically. Retention requires >=30% fewer FP and false seconds,
no lost baseline event, maximum first-alert delay no more than baseline+.25s,
and >=90% true-cell HEAD and rod recall. Report full threshold curves including
baseline operating point; no test threshold selection. A counterfactual RGB-off
and sensor-shuffle replay at the same frozen threshold checks input reliance,
without claiming a retrained ablation or information-theoretic ceiling.

This is an initial small-data feasibility pilot, not the full paired training
corpus or a hardware/natural-distribution result. A negative result establishes
only that this representation/training/data recipe failed, not that current
sensor summaries are exhausted. No paid allocation or default-App promotion.
