# MZ136: direct corridor classification with paired lateral interventions

EXPLORE, simulation only. User direction: retain inexpensive one RGB + 8x8
ToF + existing Radar + IMU; compare independent classification with the same
classification plus corridor in/out ranking. MZ129 remains runnable. Candidate
alarms are independent; no complete incumbent alarm is ORed back in.

## Difference from previous work

MZ124 already compared identical-network BCE versus BCE plus changed-cell hinge,
with complete pair-disjoint splits. It failed on training and consumed development;
this is not a previously untried generic pairing mechanism. MZ136 changes the
supervised task from 45-cell occupancy to one current-corridor label. The unchanged
11,305-parameter MZ120 network produces eight central near-cell latent scores;
their log-mean-exp is the corridor score. These latent outputs are not claimed
as spatial occupancy, return identity, calibrated probability, or clear space.

Both arms have identical initial tensors, pair batches, RGB, sensor observations,
optimizer, steps and augmentation arrays. Classification is unweighted frame BCE;
the candidate adds `0.25 * relu(1 - (s_a-s_b)*(y_a-y_b))` for differently labelled
members. No source/depth reconstruction loss, MERGED subnetwork, new sensor,
backbone or temporal state is added. The single margin is 1 logit unit.

## Fit diagnosis before capture

Use 24 aligned frame pairs (48 frames, all four families) from consumed MZ123
pair0, selecting every second timestamp. This is a fit check, not new independent
evidence. At threshold zero require both fits >=95% frame accuracy and >=90%
both-members-correct. First matched 800-step fit with paired brightness/contrast
augmentation gave BCE 24/5/0 and pair 24/6/0 TP/FP/FN; do not hide this failure.

Errors span rod, boundary, BODY and HEAD; loss remains nonzero under stochastic
augmentation. One bounded optimization diagnostic uses 2,400 steps and no image
augmentation to ask whether the unchanged observation representation can fit
the actual examples. Both arms restart from the same seeded initial tensors.
This jointly changes training duration and augmentation for a fitting diagnostic,
so it cannot isolate which change explains any repair. No UE capture starts
until the fit prerequisite passes. Failure triggers input/optimization diagnosis,
not a claim of sensor information insufficiency.

remain at 45/48 correct and 21/24 both-correct under the original zero threshold;

Training-only scalar threshold calibration gives each 46/48 correct and 22/24
both-correct. This separates a score/readout offset from failure to learn most
pair differences. Admit the new grouped comparison on this explicitly revised,

New thresholds still come exclusively from its separate development groups.

## New grouped source and paired comparison

Prepare 24 new procedural base scene groups, four obstacle families. Each has
two lateral intervention episodes and six timestamps (288 frames). Four groups
per family train, one develops, one evaluates: 192/48/48 frames. Geometry/texture
background identities and all intervention versions remain in one partition;
distances are not systematically assigned by partition. Within each pair,
shape, appearance, camera, non-target objects and seed are shared; only the
target's lateral placement/trajectory changes. Re-render RGB and regenerate ToF,
Radar and IMU for every member. Same seeds do not promise identical conditional
noise-draw alignment when the number of returns changes.

The source generator audits labels, pairing and disjointness before capture.
All physical context actors remain in native truth. This is new held-out
procedural scene-group evidence within the same simulator, not natural-background
generalization or hardware confirmation. Removal and texture-invariance training
are omitted to keep this round focused on the lateral intervention.

After fit admission, the default full comparison is two 2,400-step fits with
the same paired augmentation as the first pilot, batch eight (four pairs),
AdamW lr .001, weight decay .0001. Twenty minutes per fit is the wall cap.
Assess full-training fit before selecting thresholds or reading evaluation
outcomes. Any development repair must be documented before evaluation; no
held-out-outcome tuning or automatic successor experiment.

## Alert acceptance and small generator perturbation

Use MZ129's retained Radar-extent arm reproduced on old 288-frame predictions
before applying the same code to the new source. Score BCE and paired candidates
independently. Development selects each candidate's threshold on a 101-point
sigmoid grid, minimizing FP among points with recall within two percentage points
of MZ129 and no lost incumbent-detected event or per-event delay over .25s.
If no point qualifies, report no feasible selection instead of choosing from test.
Freeze checkpoints, thresholds and source identities before held-out evaluation.

Report frame TP/FP/FN/TN, no-alert/UNKNOWN count, family recall, event detections,
each event's first alert and false segments/duration. Preserve actual removed
and new errors and independently retained native observations. No-alert means
uncalibrated no-alert, never certified clear. Missing events cannot disappear
from a delay average. Pair order and both-correct rates are supporting metrics.

The investment target is >=20% FP reduction versus MZ129 with similar recall
and event timing, maintained under one fixed within-zone ray-position shift.
Attribution to pairing additionally needs improvement over matched BCE under
the same retention criteria; if BCE is as good, retain the simpler method.
This small single-seed result is an exploratory comparison, not a significance
or deployment claim. The old 288 frames remain a disclosed development recheck.

Perturb only the ToF ray sampling positions, fixed 8x8 zones and 3x3 rays each,
same signal budget and reduction/noise model. Admit the analytic first-hit proxy
against native ray evidence before generating a shifted packet set. Retain RGB,
Radar, IMU and labels exactly. Recompute MZ129 and both candidates on the same
perturbed observations using frozen thresholds, without retraining. One
perturbation is a sensitivity check, not comprehensive simulator robustness.
